# «Сокол» — архитектура страниц (по структуре QMonitoring + наши козыри)

Дата: 2026-10-23 · к показу «ПроИИ» пн 26.10 · просьбы Юлая msg 8288, 8291, 8293, 8298
Карта конкурента — [qmonitoring-map.md](qmonitoring-map.md). Прототипы — `0N-*.html` рядом, снимки — `shots/`.

**Метки:** **работает к 26.10** — страница на живых данных (API спеки 005, контракт v0); **пример** — прототип с правдоподобными данными, на экране плашка «Пример · в разработке»; **план** — справочная страница без данных.
Облик главного экрана выбирается отдельно (концепты в `.artifacts/sokol/proto/screens/`, msg 8298), здесь он — схема блоков. Все страницы стоят на тех же токенах, что концепты главного экрана: `build.py` берёт блоки `:root` из `.artifacts/sokol/proto/screens/tokens.css` в `assets/tokens.css` и добавляет мост имён; тема — `data-theme` как у концептов (по умолчанию — по системе). Сменились токены концептов — `python3 build.py`, страницы сходятся сами. Подрядчик — точка 8 px тоном `--co-a/b/c`, как в концептах.

## Навигация

Как у QMonitoring (`Q/q06.jpg`, `L/natt__*`): рейка слева на компьютере, нижняя панель из 5 вкладок на телефоне; шапка страницы — площадка, источник и смена, справа действия страницы. Пункты: **Пульт · Рейсы · Табель · Сводка · Объекты · Что дальше**. «События» у QMonitoring = наша очередь «Подтвердить» и лента — живут на пульте, отдельной страницы нет (их «Мгновенный инцидент» каждые 30 с — шум, `Y/…incidents-table__02`).

## Что берём у QMonitoring · что делаем лучше · чего не берём

- **Берём структуру:** рейку разделов, шапку «объект · источник · смена», вкладки камер над кадром, ленту событий по камерам на шкале, состояние камер с причиной, таблицу с фильтрами в одну строку и «Скачать», окно доказательства, сводку «фильтр → 4 плитки → график → разбивка», карточки объектов.
- **Лучше:** машина — личность (номер табличкой и вырезкой, «чей»), рейс «въехал → не видно, таймер идёт → выехал · N мин», «Тот же?» и «подтверди» вместо шумных «мгновенных инцидентов», табель «заявлено ↔ видели» и выгрузка для 1С, честность «k из n» и «не видно ≠ стоит», рубли — только из ставок заказчика.
- **Не берём:** их облик (бренд, лого, красно-оранжевый и жёлтый, тексты), красные «Помощь» в каждой строке, «точность 95 %» одной цифрой, модули без своих данных.

## Главный экран — сетка для сборщика (схема 01-pult.html)

Раскладка — блоками, облик подставит выбранный концепт. Компьютер 1440×900:

```
.app      grid: [rail 72px] [main 1fr]
.main     grid-template-rows: 64px (шапка) 1fr
.body     grid-template-columns: 420px minmax(0,1fr); gap: var(--gap); padding: 20px 24px
  .list   строки машин var(--row) = 56px; вкладки «Машины · Подтвердить · События»; подвал «пределы»
  .center grid-template-rows: 84px (4 цифры) auto (вкладки камер 44px + окно 16:9) auto (низ)
           окно по высоте экрана: width = min(100%, (100vh − 500px) · 16/9), по центру — пульт целиком в 1440×900
    #cam-slot  data-module="camera-window" data-camera="campus-1" — контейнер 16:9, position:relative;
               модуль окна камеры монтируется внутрь целиком (видео, рамки, номера треков, переключатель рамок)
    .bottom    grid-template-columns: 1fr 280px
      #cam-strip data-module="event-strip" — строка на камеру, шкала часа/смены, метки въезд / выезд / стоит / не видно, «сейчас»
      .plan      схема площадки: зоны (въезд · стоянка · котлован · бытовки) и точки машин той же формой, что в списке; данные — plan_xy
```

Телефон 390: шапка с «Подтвердить N» → 4 цифры 2×2 → список машин → вкладки камер (прокрутка) и окно камеры → лента → схема; нижняя панель 5 вкладок (techspec §6.3: «одна колонка — выездное меню, под ним камера»).
